## 3. #136 – Kamera-/Bildschirmfehler LINK:38 ist im Kodi-Log verifiziert, aber die Quelle ist spezifisch **CAPTURE_TARGET**
**`kodi.old.log` mit .28:**
- **23:55:06** `[XCMate][CAPTURE_TARGET] code=TARGET_ATOMIC_PUBLISH_UNAVAILABLE syscall=LINK errno=38`.
- **23:55:17** und **23:56:16** `CAPTURE_TARGET READY / RENAME_NOREPLACE / 0`.
- **23:56:00** `CAPTURE_TARGET UNSUPPORTED_TARGET / PATH / 0`.

**`kodi.log` nach .29-Upgrade:**
- **09:23:04** `CAPTURE_TARGET UNSUPPORTED_TARGET / PATH / 0`;
- **09:23:11** `CAPTURE_TARGET READY / RENAME_NOREPLACE / 0`;
- **09:23:43** `CAPTURE_TARGET TARGET_ATOMIC_PUBLISH_UNAVAILABLE / LINK / 38`;
- **09:29:13** und **09:29:54** `CAPTURE_TARGET READY / RENAME_NOREPLACE / 0`.

**Logbeweis/Abgrenzung:** `errno=38` unter Android Linux = `ENOSYS`, `os.link()` bzw. der angefragte native atomare Veröffentlichungsschritt nicht verfügbar; dies bedeutet **nicht**, dass physischer USB/SMB generell nicht beschreibbar ist. **Die Marker stammen aus der Kategorie `CAPTURE_TARGET` (Aufnahmeziel-Prüfung), nicht aus einem `DOWNLOAD_TARGET`-Marker.** Es gibt *keinen* vorhandenen sanitierten Trace, der für diese Vorgänge die gewählte XCMate-Menüaktion, ob `smb://` korrekt ausgewählt und ob `download_targets.assess` / `_usb_probe` / `_smb_probe` / `stage_root` tatsächlich ausgeführt wurden, ausweist. Daher keinen feststehenden Download-Backend-Fix aus der Meldung ableiten.

**Codekontext:** `home_menu.py` hat **separate** Aktionen `download_folder` und `recording_folder`; `download_target_ui.py::choose` öffnet Picker mit `defaultt=old`, also gerade **nicht** mit Quellen-/Laufwerksübersicht. `capture_target.probe` ist POSIX-native-only; `download_targets.assess` hat USB-Stage- und SMB2-Backends, aber `stage_root()` verwendet intern ebenfalls `atomic_media.probe`. Weitere Fehler könnten an der **internen Staging-Prüfung** entstehen, selbst wenn ein USB-Datenträger grundlegendes Schreiben erlaubt; das ist **noch zu verifizieren**.

**Codex:**
1. Unmissverständliche Menüpunkte „**Downloadziel wählen**“ vs „**Aufnahmeziel wählen**“; Picker startet **Quellenübersicht**: Kodi intern / USB-Geräte / Kodi SMB-Freigaben. Keine stille interne Default-Rückwahl; gewählten Target-Typ behalten und Fehler erklären.
2. Datensparsame Marker: `PICKER_ACTION=DOWNLOAD|RECORD`, `PICKER_ROOT_LISTED`, `TARGET_CLASS=LOCAL|USB|SMB`, `TARGET_PROBE_PHASE=NATIVE|USB_STAGE|SMB2|STAGING_LOCAL`, `FAILED_CODE/STEP/ERRNO`, `TARGET_BOUND`, `PERSIST_OK`. Keine Zielpfade, Hosts, Credentials, Zugangsdaten in öffentlichen Logs.
3. Externe USB-Fähigkeiten und SMB-Signierung separat absichern; staging auf wirklich sicheren internem Dateisystem oder technisch geprüfter alternativer no-overwrite-Lösung, keine Sicherheitsprüfungen pauschal deaktivieren. Datei größer als FAT32-Limit, Teildatei/Netzabbruch, Schreib-/Lesetest und Hash-Verifikation abnehmen. **SMB nie ohne erreichbaren Server als offline deklarieren**.
4. Speichergates ST01–ST07 und Recording CAP01/CAP02 weiterhin **vom Nutzer FAIL markiert**, technische Folgetests größtenteils durch Zielwahl blockiert. **Keine** automatische PASS-/Issue-Schließung.
