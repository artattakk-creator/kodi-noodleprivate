## Festgelegter API-Vertrag v1, noch kein produktiver Server

- `POST /v1/pair/start`: zufälliger 48-Byte-Installationsverifier bleibt privat, Request enthält nur seinen SHA256-Challenge und `S256`. Antwort: separater kryptographisch starker `device_code`, kurzer `user_code`, 30–600 Sekunden Gültigkeit, Pollintervall 5–60 Sekunden. Der sichtbare Freigabecode ist **keine** Geräteberechtigung.
- `POST /v1/pair/poll`: privater Device-Code und Verifier ausschließlich im TLS-Body. Server prüft Challenge, Ablauf, Adminfreigabe und einmalige atomare Ausgabe; PENDING ist kein Erfolg. Nach PAIRED werden Device-Code/Verifier durch eine gerätespezifische zufällige Berechtigung ersetzt. Vor lokalem Commit muss die signierte Statusprüfung erfolgreich sein.
- `POST /v1/status`, `/v1/tmdb`, `/v1/revoke`: Geräte-ID, UTC-Zeit, zufällige Nonce und HMAC-SHA256-Proof über `operation\ntime\nnonce\nsha256(body)` in Headers, ausschließlich unter verifiziertem TLS. Kein zentraler TMDB-Token. Der Server muss Uhrtoleranz (höchstens 30 Sekunden), pro Gerät atomaren Replay-Schutz und Widerruf prüfen. Manuelle Rotation: widerrufen und neu koppeln. Kurzlebige/asymmetrische Credentials sind eine mögliche weitere Härtung, hier nicht als umgesetzt ausgegeben.
- Erlaubt: configuration, search TV/movie/person, numerische TV-/Movie-Werke und definierte alternative_titles/external_ids/images/credits; eng begrenzte Query-Schlüssel/-längen, keine doppelten Parameter. Server muss dieselbe Allowlist unabhängig durchsetzen; zentrale Upstream-Autorisierung ausschließlich serverseitig.

## Nachtrag K1: einfacherer einmaliger Import, ausdrücklich anderer Schutz

Die UI bietet zuerst den freiwilligen einmaligen Tokenimport, danach die stärkere Gateway-Option. Der Endpunkt bleibt leer/deaktiviert; `PROPOSED_SERVER=https://gs-media.eu` ist ausschließlich Metadatum und keine Behauptung existierender API-Routen. Vor Start wird ausdrücklich erklärt: Der globale Token liegt danach auf der Box; Root/kompromittierte Geräte können ihn auslesen, Gerätewiderruf allein sperrt eine bereits ausgegebene Kopie nicht.

Dasselbe Challenge-/Admin-Pairing mit Modus `token_once`; nur für die gebundene `pair/poll`-Antwort dieses Modus ist `TOKEN_ONCE` mit zentralem Token zulässig. In Gateway-/Status-/Metadatenantworten bleibt ein solcher Wert verboten. Vor Schreiben syntaktisch validieren und eine autorisierte TMDB-configuration-Abfrage im RAM prüfen; danach ausschließlich bestehender privater `token_write64` mit absent-only Vergleich, Profilprüfung, fsync/Replace/Readback. Bestehende lokale Datei oder Legacy-Zugang verhindert erneute Provisionierung. Keine öffentliche Token-Datei, keine Übertragung im Query/Redirect/Journal, kein stiller Moduswechsel.

Installer-SDK verwendet explizite XCMate-Settings und die vorhandenen Übersetzungskataloge, auch wenn der Aufrufer `script.gsmedia.setup` heißt. Die neue Funktion `localization.tr_for_addon` erweitert dieselbe Architektur. Zusätzliche Tests prüfen einmaligen Import/Neustart, Ablehnung im falschen Modus, fehlgeschlagenen Auth-Test ohne neue Datei und korrekte Settings-Eigentümerschaft. Der authentifizierte echte Server, einmalige atomare Ausgabe, Admin-MFA, Replay-/Rate-Limits und die TMDB-Nutzungsfreigabe bleiben **BLOCKED** bis zur separaten Umsetzung/Bereitstellung. Keine echte Tokenübertragung durchgeführt.
