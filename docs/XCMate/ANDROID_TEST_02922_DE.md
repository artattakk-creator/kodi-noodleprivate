# Android-Abnahme – kumulatives Update XCMate 0.1.29.21 → 0.1.29.22

**Alle Punkte: NOT_TESTED bis zur echten Nutzerabnahme.** **Ausnahme B02 (automatischer Staffelwechsel): vom Nutzer ausdrücklich vertagt; kein aktiver Pflichtpunkt.** Ziel: Kodi 21.2 Omega, Android 13 ARM32, Titan BINGIE MOD, IR; möglichst zusätzlich Estuary und 720p/1080p.

Dieser Kandidat enthält sämtliche .21-Autoplay-/Player-Funktionen, EPG-Korrekturen und das verifizierte Original-Icon. **Direkt über die installierte .21 aktualisieren. Keine Deinstallation, kein Downgrade auf .20, kein Reset.** Ältere isolierte .22-ZIPs sind ungültige Updatekandidaten; nur den neu bezeichneten kumulativen ZIP und dessen neue SHA256 aus PR #110 verwenden.

1. **Vorher .21 unverändert lassen.** Version, bestehendes Portal, gespeicherte Startgruppe/Startsender, eine Favoritenmarkierung, eine Resume-Position und bereits sichtbare Cover merken. Keine Konfiguration zur Vorbereitung löschen oder neu importieren.
2. Neuen kumulativen `plugin.video.xtreammate-0.1.29.22.zip` und passende `.sha256` laden, SHA256 vergleichen. Kodi → Add-ons → Aus ZIP-Datei installieren → dieses ZIP auswählen. Die vorhandene Add-on-ID bleibt `plugin.video.xtreammate`; Installation muss .21 ersetzen, kein zweites Add-on anlegen. Version .22 kontrollieren.
3. **Portale/Einstellungen prüfen.** Konten, Sendergruppen, Startgruppe/Startsender und bestehende EPG-Zuordnungen sind weiter vorhanden. Keine Neusynchronisierung oder Portal-Neueinrichtung ausführen. Bei Abweichung FAIL mit genauer Beobachtung.
4. **Serien-Autoplay:** mindestens drei vollständige Folgen natürlich auslaufen lassen, ohne jeweils OK zu drücken. Nächste gültige Episode muss derselben Serie und demselben Portal angehören. **Kein aktiver Staffelwechseltest B02:** Dieser Punkt wurde auf Nutzerwunsch aus den geführten Tests herausgenommen. Falls sich bei normaler Nutzung zufällig ein Staffelwechsel zeigt, kann er gemeldet werden. Das bisherige Ergebnis für #85 bleibt NOT_TESTED/vertagt und wird erst nach ausdrücklicher Erfolgsmeldung des Nutzers auf GitHub als PASS dokumentiert; anschließend #85 schließen. Keine Specials oder Rückkehr zu Folge 1. Für Fortschrittsprüfung Episoden mindestens 60 Sekunden, sinnvoll 2–3 Minuten; mindestens einen Ablauf ohne Seek prüfen.
